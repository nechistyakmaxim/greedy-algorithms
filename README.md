# Жадные алгоритмы. Как принимать решения “на лету”
В мире программирования и алгоритмического мышления существует множество подходов к решению задач оптимизации. Один из самых интуитивно понятных и часто применяемых — **жадные алгоритмы** (greedy algorithms). Их суть заключается в том, чтобы на каждом шаге принимать **локально оптимальное решение**, надеясь, что в итоге это приведёт к **глобально оптимальному результату**.

Хотя жадные алгоритмы не всегда гарантируют наилучшее решение, они просты в реализации, эффективны по времени и памяти, и в ряде задач дают точный или близкий к оптимальному результат. В этой статье мы разберём принцип работы жадных алгоритмов, их плюсы и минусы, а также покажем практические примеры на языке 1С:Элемент.

## Что такое жадный алгоритм?

Жадный алгоритм — это стратегия решения задачи, при которой на каждом шаге выбирается наиболее выгодный вариант, без учёта будущих последствий. Такой подход «жаден»: он берёт максимум здесь и сейчас, не думая о том, что будет дальше.

### Когда жадный алгоритм работает?

Жадные алгоритмы дают оптимальное решение только в задачах, обладающих двумя ключевыми свойствами:

1. Свойство жадного выбора — локально оптимальный выбор ведёт к глобальному оптимуму.
2. Оптимальная подструктура — оптимальное решение всей задачи содержит в себе оптимальные решения подзадач.

Примеры таких задач:

- Задача о выборе заявок (Activity Selection Problem)
- Алгоритм Хаффмана для сжатия данных
- Минимальное остовное дерево (алгоритмы Краскала и Прима)
- Задача о сдаче (минимальное количество монет)

## Преимущества и недостатки

### Плюсы:

- Простота реализации
- Быстродействие (часто линейная или логарифмическая сложность)
- Низкое потребление памяти

### Минусы:

- Не всегда дают оптимальное решение
- Требуют доказательства корректности для конкретной задачи

## Примеры жадных алгоритмов в 1С:Элемент

Рассмотрим несколько практических примеров, где жадные стратегии могут быть полезны в типичных бизнес-задачах, решаемых в 1С.

### Пример 1. Выбор наиболее выгодных заказов за день (задача о заявках)

**Постановка задачи**:  
У вас есть список заказов клиентов. Каждый заказ имеет время начала и окончания. Нужно выбрать максимальное количество заказов, которые не пересекаются по времени (например, для одного менеджера или склада).

**Жадная стратегия**:  
Сортируем заказы по времени окончания и последовательно выбираем те, которые начинаются не раньше окончания предыдущего.

#### Реализация на 1С:Элемент
```
// ---------------------------------------------
// Жадный алгоритм: выбор непересекающихся заказов
// ---------------------------------------------
//
// Идея: выбираем заказы, которые не пересекаются по времени,
// чтобы обслужить максимум клиентов за день.
//
// Пример из жизни:
// Представим, что у нас есть один курьер,
// и несколько заказов с разным временем выполнения.
// Курьер не может взять два заказа, если они пересекаются по времени.
//
// Стратегия жадного алгоритма:
// - сортируем все заказы по времени окончания;
// - выбираем первый (он заканчивается раньше всех);
// - затем берем следующий, который начинается после окончания предыдущего;
// - повторяем, пока не закончатся заказы.
//
// Такой подход "жадный", потому что в каждый момент
// мы выбираем самое выгодное локальное решение — заказ,
// который освободит курьера как можно раньше.
// Это решение оказывается и глобально оптимальным.
//
// ---------------------------------------------

структура ЗаказПокупателя
    знч ВремяНачала: ДатаВремя       // когда заказ начинается
    знч ВремяОкончания: ДатаВремя    // когда заказ заканчивается
    знч Клиент: Строка               // имя клиента
    знч Сумма: Число                 // сумма заказа
;

метод Скрипт()
	
    // ---------------------------------------------
    // 1. Создаем список заказов
    // ---------------------------------------------
    знч ЗаказыСегодня = новый Массив<ЗаказПокупателя>()
    
    ЗаказыСегодня.Добавить(новый ЗаказПокупателя(ДатаВремя{2025-10-19 08:00}, ДатаВремя{2025-10-19 09:00}, "ООО Ромашка", 3000))
    ЗаказыСегодня.Добавить(новый ЗаказПокупателя(ДатаВремя{2025-10-19 09:30}, ДатаВремя{2025-10-19 10:30}, "ООО Тюльпан", 2000))
    ЗаказыСегодня.Добавить(новый ЗаказПокупателя(ДатаВремя{2025-10-19 09:00}, ДатаВремя{2025-10-19 11:30}, "ООО Лотос", 4000))
    ЗаказыСегодня.Добавить(новый ЗаказПокупателя(ДатаВремя{2025-10-19 10:40}, ДатаВремя{2025-10-19 12:00}, "ООО Георгин", 3500))
    ЗаказыСегодня.Добавить(новый ЗаказПокупателя(ДатаВремя{2025-10-19 11:50}, ДатаВремя{2025-10-19 13:00}, "ООО Фиалка", 2500))
	
    // ---------------------------------------------
    // 2. Применяем жадный алгоритм
    // ---------------------------------------------
    знч Оптимальные = ВыбратьНепересекающиесяЗаказы(ЗаказыСегодня)
	
    // ---------------------------------------------
    // 3. Выводим результат
    // ---------------------------------------------
    Консоль.Записать("Оптимальный график заказов:")
    пер ОбщаяСумма = 0
    
    для Заказ из Оптимальные
        // Выводим каждого клиента и время его заказа
        Консоль.Записать(
            Заказ.Клиент 
            + " (" + Заказ.ВремяНачала.Представление("ЧЧ:мм") + "-" + Заказ.ВремяОкончания.Представление("ЧЧ:мм") + ") " 
            + "Сумма: ${Заказ.Сумма}"
        )
        ОбщаяСумма = ОбщаяСумма + Заказ.Сумма
    ;
	
    // Выводим итоги
    Консоль.Записать("")
    Консоль.Записать("Всего заказов: ${Оптимальные.Размер()}, общая сумма: ${ОбщаяСумма}")
    
;

// ---------------------------------------------
// Функция выбора непересекающихся заказов
// ---------------------------------------------
//
// На вход: массив заказов.
// На выход: массив заказов, которые можно выполнить без пересечений.
//
// Принцип:
//   1. Сортируем по времени окончания — сначала те, что заканчиваются раньше.
//   2. Перебираем заказы по очереди.
//   3. Если заказ не пересекается с предыдущим — добавляем его в результат.
// ---------------------------------------------

метод ВыбратьНепересекающиесяЗаказы(МассивЗаказов: Массив<ЗаказПокупателя>): Массив<ЗаказПокупателя>
	
    // Шаг 1. Сортировка по времени окончания (самые "короткие" заказы первыми)
    // Важно: сортировка по возрастанию, чтобы сначала рассматривать ранние заказы.
    МассивЗаказов = МассивЗаказов.СортироватьПо(Элемент->Элемент.ВремяОкончания, НаправлениеСортировки.ПоВозрастанию)
	
    пер ПоследнееВремяОкончания = ДатаВремя{}  // минимальная дата
    знч Результат = новый Массив<ЗаказПокупателя>()
	
    // Шаг 2. Перебираем все заказы и выбираем только непересекающиеся
    для Заказ из МассивЗаказов
        // Проверяем: если заказ начинается после окончания предыдущего — берем его
        если Заказ.ВремяНачала >= ПоследнееВремяОкончания
            Результат.Добавить(Заказ)
            ПоследнееВремяОкончания = Заказ.ВремяОкончания
        ;
    ;
	
    // Возвращаем список выбранных заказов
    возврат Результат	
;
```

Результат

```
Оптимальный график заказов:
ООО Ромашка (08:00-09:00) Сумма: 3 000
ООО Тюльпан (09:30-10:30) Сумма: 2 000
ООО Георгин (10:40-12:00) Сумма: 3 500

Всего заказов: 3, общая сумма: 8 500
```
### Пример 2. Минимизация количества монет при выдаче сдачи

**Постановка задачи**:  
В кассе нужно выдать сдачу минимальным количеством монет/купюр. Допустим, номиналы: 1000, 500, 100, 50, 10, 5, 1 рубль.

**Жадная стратегия**:  
Брать максимально возможный номинал, пока сдача не станет нулевой.

#### Реализация на 1С:Элемент
```
// ---------------------------------------------
// Жадный алгоритм: минимизация количества монет
// ---------------------------------------------
//
// Задача:
//   Выдать сумму сдачи минимальным количеством монет.
//
// Пример из жизни:
//   Нужно вернуть клиенту сдачу 87 рублей, 
//   а у нас есть монеты номиналом 10, 5, 2 и 1 рубль.
//
// Идея жадного алгоритма:
//   На каждом шаге берем **самую крупную монету**, 
//   которая меньше или равна оставшейся сумме.
//   Так сумма уменьшается максимально быстро.
//
// Пример работы:
//   Сдача = 87
//   Берем 10 → остаток 77
//   Берем 10 → остаток 67
//   ...
//   Когда больше нельзя взять 10, переходим к 5, потом к 2 и 1.
//
// ---------------------------------------------

метод Скрипт()

    знч Монеты = новый Массив<Число>()
    Монеты.Добавить(10)
    Монеты.Добавить(5)
    Монеты.Добавить(2)
    Монеты.Добавить(1)

    знч Сдача = 87
    
    Консоль.Записать("Сдача: ${Сдача} руб.")
    Консоль.Записать("Доступные монеты: ${Монеты}")

    знч Результат = РассчитатьМинимумМонет(Сдача, Монеты)

    Консоль.Записать("")
    Консоль.Записать("Выдача сдачи:")
    пер ОбщаяКоличество = 0

    для Элемент из Результат
        Консоль.Записать("Монета: ${Элемент.Ключ}, количество: ${Элемент.Значение}")
        ОбщаяКоличество = ОбщаяКоличество + Элемент.Значение
    ;

    Консоль.Записать("")
    Консоль.Записать("Всего монет: ${ОбщаяКоличество}")

;


// ---------------------------------------------
// Функция жадного расчета количества монет
// ---------------------------------------------
//
// На вход:
//   СуммаСдачи — сколько нужно выдать
//   МассивМонет — доступные номиналы монет
//
// На выход:
//   Список пар (номинал → количество)
//
// Алгоритм:
//   1. Сортируем монеты по убыванию.
//   2. Для каждой монеты берем максимально возможное количество.
//   3. Уменьшаем остаток сдачи.
// ---------------------------------------------

метод РассчитатьМинимумМонет(СуммаСдачи: Число, Монеты: Массив<Число>): Соответствие<Число, Число>

    // Шаг 1. Сортируем монеты по убыванию (от крупных к мелким)
    Монеты = Монеты.СортироватьПо(Элемент->Элемент, НаправлениеСортировки.ПоУбыванию)

    пер Остаток = СуммаСдачи
    знч Результат = новый Соответствие<Число, Число>()

    // Шаг 2. Перебираем монеты
    для Монета из Монеты
        если Остаток >= Монета
            знч Количество = (Остаток / Монета).ЦелаяЧасть()
            Результат.Вставить(Монета, Количество)
            Остаток = Остаток - (Количество * Монета)
        иначе
            Результат.Вставить(Монета, 0)
        ;
    ;

    // После завершения цикла Остаток должен быть 0
    если Остаток > 0
        Консоль.Записать("⚠ Не удалось выдать сдачу полностью! Остаток: ${Остаток}")
    ;
    возврат Результат
;
```

Результат
```
Сдача: 87 руб.
Доступные монеты: [10, 5, 2, 1]

Выдача сдачи:
Монета: 10, количество: 8
Монета: 5, количество: 1
Монета: 2, количество: 1
Монета: 1, количество: 0

Всего монет: 10
```

### Пример 3. Распределение бонусов между клиентами

**Постановка задачи**:  
У вас есть фиксированный бюджет на бонусы (например, 100 000 руб.). Нужно распределить его между клиентами так, чтобы **максимизировать количество довольных клиентов**. Клиент считается довольным, если получил бонус ≥ его ожидаемой суммы.

**Жадная стратегия**:  
Сортируем клиентов по возрастанию ожидаемой суммы и выдаём бонусы, начиная с самых «скромных».

### Реализация на 1С:Элемент
```
// ---------------------------------------------------------
// Жадный алгоритм: максимизация довольных клиентов
// ---------------------------------------------------------
//
// Условие:
//   Есть бюджет = 100000 руб.
//   Каждый клиент ожидает получить некоторую сумму бонуса.
//
// Цель:
//   Максимизировать количество "довольных" клиентов,
//   т.е. тех, кто получил бонус >= ожидаемого.
//
// Жадная стратегия:
//   Сначала обслуживаем клиентов с минимальными ожиданиями.
//
// Пример:
//   Бюджет = 100000
//   Ожидания = [15000, 40000, 5000, 10000, 30000]
//   → выдаем: 5000, 10000, 15000, 30000, 40000
//   итого тратим 100000 и радуем 5 клиентов!
//
// ---------------------------------------------------------

метод Скрипт()

    знч Бюджет = 110000
    знч Ожидания = новый Массив<Число>()
    Ожидания.Добавить(15000)
    Ожидания.Добавить(40000)
    Ожидания.Добавить(5000)
    Ожидания.Добавить(10000)
    Ожидания.Добавить(30000)

    Консоль.Записать("Общий бюджет: ${Бюджет}")
    Консоль.Записать("Ожидания клиентов: ${Ожидания}")

    знч Результат = РаспределитьБюджет(Бюджет, Ожидания)

    Консоль.Записать("")
    Консоль.Записать("Результат распределения:")

    Консоль.Записать("Довольных клиентов: ${Результат.Довольные}")
    Консоль.Записать("Израсходовано: ${Результат.Потрачено}")
    Консоль.Записать("Остаток: ${Результат.Остаток}")

;


// ---------------------------------------------------------
// Функция распределения бюджета
// ---------------------------------------------------------
//
// На вход:
//   Бюджет — сумма денег
//   Ожидания — массив запросов клиентов
//
// На выход:
//   Структура с итогами: Довольные, Потрачено, Остаток
//
// ---------------------------------------------------------

структура РезультатРаспределения
    пер Довольные: Число
    пер Потрачено: Число
    пер Остаток: Число
;

метод РаспределитьБюджет(Бюджет: Число, Ожидания: Массив<Число>): РезультатРаспределения

    // Шаг 1. Сортируем клиентов по возрастанию ожиданий
    Ожидания = Ожидания.СортироватьПо(Элемент->Элемент, НаправлениеСортировки.ПоВозрастанию)

    пер Потрачено = 0
    пер Довольные = 0

    // Шаг 2. Перебираем ожидания
    для Ожидание из Ожидания
        если Потрачено + Ожидание <= Бюджет
            Потрачено = Потрачено + Ожидание
            Довольные = Довольные + 1
        иначе
            // Денег не хватает — выходим из цикла
            прервать
        ;
    ;

    знч Остаток = Бюджет - Потрачено
    знч Результат = новый РезультатРаспределения(Довольные, Потрачено, Остаток)
    возврат Результат
;

```

Результат:

```
Общий бюджет: 110 000
Ожидания клиентов: [15000, 40000, 5000, 10000, 30000]

Результат распределения:
Довольных клиентов: 5
Израсходовано: 100 000
Остаток: 10 000
```

## Заключение

Жадные алгоритмы — это мощный инструмент для задач, где можно принимать **локально оптимальные решения на каждом шаге**. Их сила заключается в простоте и скорости: вместо того чтобы рассматривать все варианты сразу, мы действуем “на лету”, выбирая наилучший вариант в текущий момент.
В статье мы рассмотрели несколько наглядных примеров:

1. Выбор непересекающихся заказов — классическая задача планирования, где жадный алгоритм позволяет составить оптимальный график заказов, максимизируя количество обслуженных клиентов.
2. Минимизация количества монет при выдаче сдачи — каждый раз выбирая самую крупную монету, алгоритм быстро и эффективно уменьшает оставшуюся сумму, обеспечивая минимальное количество монет.
3. Распределение бонусов среди клиентов при ограниченном бюджете — сначала удовлетворяем клиентов с наименьшими ожиданиями, чтобы максимизировать число довольных клиентов, используя весь доступный ресурс рационально.

Эти примеры показывают, что жадные алгоритмы особенно полезны, когда:
- задача имеет **локально оптимальные шаги**, которые ведут к глобальному оптимуму;
- важно **принимать решения быстро**, без полного перебора всех вариантов;
- необходимо **максимально использовать ресурсы** или время.

Однако важно помнить: жадные алгоритмы не всегда гарантируют глобально оптимальное решение для всех типов задач. Иногда требуется более сложная оптимизация, динамическое программирование или перебор всех вариантов.

Тем не менее, как мы видели на примерах, для множества практических задач жадный подход — это простой, быстрый и наглядный способ принимать решения “на лету”, экономя время и ресурсы, что делает его незаменимым инструментом в арсенале разработчика и аналитика.
